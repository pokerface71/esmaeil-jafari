# راه‌اندازی بخش مقالات (Supabase)

## ۱. ساخت پروژه Supabase (رایگان)

1. به [supabase.com](https://supabase.com/dashboard) بروید و با GitHub ثبت‌نام/ورود کنید.
2. **New project** را بزنید، یک نام بدهید و یک Region نزدیک (مثلاً Frankfurt) انتخاب کنید.
3. حدود ۲ دقیقه صبر کنید تا پروژه ساخته شود.
4. پلن **Free** شامل: دیتابیس ۵۰۰ مگابایتی، ۵۰ هزار کاربر ماهانه، ۱ گیگابایت Storage و ۲ پروژه فعال — برای بلاگ شخصی کاملاً کافی است.

## ۲. ساخت جداول

1. در منوی چپ **SQL Editor** را باز کنید.
2. محتوای فایل `supabase/schema.sql` را کپی و اجرا (**Run**) کنید.
3. حالا دو جدول `posts` و `post_translations` با سیاست‌های امنیتی RLS ساخته شده است.

## ۳. غیرفعال کردن ثبت‌نام عمومی (مهم برای امنیت)

1. منوی چپ → **Authentication → Sign In / Providers**.
2. گزینه **Allow new users to sign up** را **خاموش** کنید.
3. با این کار فقط خودتان می‌توانید با ایمیلِ ساخته‌شده در مرحله بعد وارد پنل ادمین شوید.

## ۴. ساخت کاربر ادمین

1. **Authentication → Users → Add user → Create new user**.
2. ایمیل و رمز دلخواه بدهید و **Auto Confirm User** را روشن بگذارید.
3. همین ایمیل/رمز را در صفحه `/admin` سایت وارد می‌کنید.

## ۵. گرفتن کلیدهای API

1. **Project Settings (⚙️) → API**.
2. دو مقدار لازم است:
   - **Project URL** → `NEXT_PUBLIC_SUPABASE_URL`
   - **anon public** key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. فایل `.env.example` را به `.env.local` کپی کنید و مقادیر را پر کنید:

```bash
cp .env.example .env.local
```

> ⚠️ کلید `anon` عمومی است و مشکلی ندارد در کد کلاینت باشد؛ امنیت با RLS تضمین شده:
> کسی جز کاربران لاگین‌شده اجازه نوشتن ندارد و بازدیدکننده‌ها فقط مقالات `published` را می‌بینند.

## ۶. اجرای محلی

```bash
npm run dev
```

- صفحه اصلی → سکشن «آخرین مقالات»
- `/blog` → لیست همه مقالات
- `/blog/SLUG` → متن کامل مقاله
- `/admin` → ورود با ایمیل/رمز مرحله ۴ و مدیریت مقالات (ساخت/ویرایش/حذف، چندزبانه، پیش‌نویس/انتشار)

## ۷. دیپلوی روی Netlify

1. در پنل Netlify: **Site configuration → Environment variables**.
2. دو متغیر `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY` را اضافه کنید.
3. **Deploy site** را بزنید تا با متغیرهای جدید دوباره بیلد شود.

## نکته‌ها

- مقاله‌ای که `Published` تیک نخورده باشد (پیش‌نویس) فقط در پنل ادمین دیده می‌شود.
- هر مقاله می‌تواند تا ۴ ترجمه (en/fa/ar/tr) داشته باشد؛ بازدیدکننده بهترین ترجمه‌ی موجود برای زبان خودش را می‌بیند (به‌ترتیب: زبان خودش ← en ← fa ← اولین ترجمه).
- محتوای مقاله **Markdown** است: `# عنوان`، `**بولد**`، `لیست`، `کد`، `لینک` و `تصویر` پشتیبانی می‌شود.
- صفحات بلاگ از ISR استفاده می‌کنند: هر ۶۰ ثانیه محتوای جدید از Supabase کش می‌شود. یعنی بعد از انتشار مقاله، حداکثر تا یک دقیقه بعد روی سایت ظاهر می‌شود.
